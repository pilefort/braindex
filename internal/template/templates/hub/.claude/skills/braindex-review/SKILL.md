# 週次レビュー

機械的な集計は `braindex review` が済ませる。ここで行うのは判断（差分の要約・放置 TODO とアーカイブ候補の扱い・次アクション）だけ。
記憶で答えず、下書きに列挙されたファイルの実物を読む。

1. hub のルートで `braindex review` を実行する。`work/review/<今日>.md` に下書きができる。
   索引・差分ファイル・放置 TODO・アーカイブ候補の 4 節は埋まっている。判断の 3 節（ダイジェスト・アーカイブ・次アクション）は見出しだけ。
   警告（終了コード 2）が出たら、飛ばしたリポ（git 管理外など）を「次アクション」に控える。
   「既にある」と言われたら、その日の下書きは作成済みなので続きから埋める。
2. 「差分ファイル（リポ別）」に列挙されたファイルの実物を読む（索引の要旨では足りない）。
   リポごとに 1〜3 行で要約し、「今週の差分ダイジェスト（リポ別）」に書く。差分の無いリポは書かない。
3. 「放置 TODO」の各項目に、続ける／やめる／いつやるか の判断を行末に添える。`work/TODO.md` 自体は持ち主のリポで直す。ここでは編集しない。
4. 「アーカイブ候補（機械条件のみ）」の各ノートを読み、結論が新しいノートで上書きされているかを判断して、
   「アーカイブ（実施・見送りと理由）」に候補ごとの 実施／見送り と理由を書く。移動も削除もしない。実施は本人の承認の後。
5. 「次アクション」に 1〜3 件書く。
6. `braindex` で索引を再生成し、`index/catalog.md` と `work/review/<今日>.md` を一緒にコミットする。
   最新のファイル名が次回の「前回日」になる。

前回日を変えるときは `braindex review -since YYYY-MM-DD`。閾値（放置 TODO の週数・アーカイブ候補の月数・初回に遡る日数）は
`braindex.json` の `review` 節。
