# 週次レビュー

機械的な手順を先に、判断を後に。機械的な手順を飛ばして記憶で答えない。

1. 索引を再生成する: hub のルートで `braindex` を実行し、件数と `git diff --stat index/catalog.md` を控える。
2. 前回レビューの日付を求める: `work/review/` の最新ファイル名（`YYYY-MM-DD.md`）。無ければ 14 日前とし、その旨をレビューに書く。
3. `root` 直下の各リポで、その日付以降に変わった知識ファイルを列挙する:
   `git log --since=<日付> --name-status -- docs/notes docs/decisions.md`。git 管理外のリポは一言添えて飛ばす。
4. 変わったファイルの実物を読み（索引の要旨では足りない）、リポごとに 1〜3 行で要約する。
5. `work/TODO.md` で 4 週間以上動いていない項目を列挙する。
6. アーカイブ候補を挙げる: 6 か月以上前で、結論が新しいノートに上書きされているもの。
   移動も削除もしない。決めるのは本人。
7. `work/review/YYYY-MM-DD.md` を次の節の順で書く: 索引（件数と差分）、リポ別ダイジェスト、放置 TODO、
   アーカイブ候補、次アクション。`index/catalog.md` と一緒にコミットする。
