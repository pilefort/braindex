# record-lint — ノート保存前の曖昧さ検査

1 つの `.md`（`docs/notes/`・`docs/decisions.md`・`work/` のメモ）を保存・追記する前に、後から読む者が事実を
もっともらしく再構成してしまう書き方を洗う。観点は `docs/conventions.md` の「結論 → 理由 → 根拠・日付つき・根拠を出せない事実は（推測）」。

使い方: `/record-lint <ノート.md のパス>`（パス省略時は対象を聞く）。

分業は他の skill と同じで、**CLI＝検出だけ／人かエージェント＝意味判断**。CLI は機械的に拾える所を漏れなく挙げ、
真偽の最終判断と修正案は本文を読んで決める。

## 手順

### 1. 対象を読む

指定された `.md` を読む。どのリポのノートかを見る（用語集 `docs/glossary.md` があれば次の手順で自動的に突き合わせる）。

### 2. CLI を走らせる

```
braindex lint <ノート.md>
```

- `ISSUE-*.md` 以外の `.md` は自動でノート検査になる（`-kind note` で固定できる）。用語集は同じリポの `docs/glossary.md` を
  自動で探す。別の場所なら `-glossary <path>`。機械可読が要るなら `-json`
- 出力は「パス:行: [種別] 内容」。終了コード 0 は指摘なし、2 は指摘あり
- 種別は 2 段階の確度:
  - **warn**（曖昧な数量詞・日付なし）… 機械的に高確度。ほぼそのまま指摘してよい
  - **candidate**（出典なき数字・裸のヘッジ・なぜ欠落・根拠欠落・未定義用語。種別名に「(候補)」が付く）… 低確度。次で判断する

### 3. 機械結果に意味判断を重ねる（ここが人かエージェントの仕事）

- **warn** はほぼ確定。曖昧な数量詞は「数値・日付に置き換えられるか」を本文から考える（例: 「最近多い」→ 実データがあれば「8/1〜8/10 で N 件」）
- **candidate** は本文を読んで真偽を確定し、偽陽性を落とす:
  - 出典なき数字 … その数字が**主張**か。主張なら一次ソース（実データ・実ページ・原文）を辿れるか。表・自明・すぐ上の行で出典済み・定義済みの定数は落とす。
    出典を出せない主張は「（推測）を付ける」か「撤回」を促す
  - 裸のヘッジ … 「たぶん／かもしれない／〜と思う／〜のはず」が、明示タグ（推測・未確認）も出典も無いまま事実の主張に付いていないか。
    付いていれば「出典を付けて検証」か「（推測）・未確認を明示」の二択に倒す。丁寧表現・引用中・自明な推量は落とす
  - なぜ欠落 … 決定・方針なのに理由が無いか（`decisions.md` は理由必須）。別の行に既にあるなら落とす
  - 根拠欠落 … 決定の 1 件に `根拠:` 行が無い。**理由と根拠は別物**。理由の一行があっても根拠（notes・データ・URL・会話の日付）へ飛べなければ残す。
    実体が無ければ「根拠: 会話 YYYY-MM-DD（ユーザー判断）」、既存で分からなければ「根拠: 不明（記録なし）」を促す。**後から根拠を再構成して埋めない**
  - 未定義用語 … 実際の `glossary.md` と突き合わせ、本当に未定義で、かつ**このリポで定義すべき語**だけ残す（一般語・固有名詞・英単語の紛れは落とす）
- `docs/decisions.md`・直前の会話の**既決と矛盾していないか**も併せて見る（矛盾があれば「これは 日付 の決定 X と矛盾する」と指摘してから直す）

### 4. 報告＋具体的な修正案を返す

残った指摘だけを、**必ず直す（warn）／検討（candidate）／却下** に分けて出す。各指摘に修正案を添える:

```
record-lint: <path>   warn <n> / candidate <n>（判断後 <m> 残）

必ず直す
- L<n> [曖昧な数量詞] 「かなり伸びた」 → 「8/1→8/10 で +N%」等の数値へ
- (doc) [日付なし] → 先頭 10 行以内に「記録日: YYYY-MM-DD」を追加

検討（意味判断で残ったもの）
- L<n> [出典なき数字] 「CPU 4.2%」に一次ソースが無い → 出典を添えるか（推測）を付す
- L<n> [なぜ欠落] 「## X を決めた」に理由が無い → 却下案も含め理由を 1 行
- L<n> [根拠欠落] 「## X を決めた」に根拠行が無い → notes・データ・URL へ、無ければ「根拠: 会話 YYYY-MM-DD（ユーザー判断）」

却下（candidate だが問題なし）
- L<n> 表のデータ行・上の行で出典済みのため対象外
```

既定は**助言のみ**（保存前の検査）。本文の自動編集はしない。直すときは確認してから。

## 注意

- CLI は検出だけを担い、価値判断はしない。語彙や検出を足すのは braindex 側の変更（テストと同じコミットで）
- 完全にローカルで処理する。ノート本文・用語集を外部に送らない
- これは **1 ノートの単体検査**。複数ノート間の相互矛盾・陳腐化は `contradiction-scan` の担当
