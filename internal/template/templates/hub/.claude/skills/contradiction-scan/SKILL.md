# contradiction-scan — 全ノート横断の矛盾・陳腐化検査

複数のノート・decisions をまたいで、**相互矛盾**（同じ事実で数値や結論が食い違う）と**陳腐化**（新しいノートや現状と
食い違う古い記述）を敵対的に洗い出す。週次レビュー（`braindex-review`）は時間的な陳腐化を提示するだけで、横断の相互矛盾は
能動的に探さない。この skill はその空きを埋める。

使い方: `/contradiction-scan [-topic <語> | -repo <名> | -dir <パス> | -full]`
（範囲の指定が無ければ、索引の見出しから点検したい話題を 1 つ選んで提案し、確認してから走る）。

索引 `index/catalog.md` の要旨は 80 字しか無い。判断は必ず**実ファイルを全文読んで**行う。

## 手順

### 1. 索引を最新化し、走査対象を絞る

```
braindex                       # hub のルートで索引を再生成する
braindex scope -topic "<語>"   # 走査対象を chunk に分けて出す(-json で機械可読)
```

- `-topic`（矛盾を探す話題を絞る。主用途）／`-repo`／`-dir`（索引を使わずフォルダを直接）／`-full`。いずれか 1 つ
- 出力は走査対象を chunk（既定 12 件）に割ったもの。パスはそのまま開ける形で出る（索引を使うときは `root` 相対、`-dir` のときは渡したディレクトリと結合した形）
- **2 件未満は突き合わせられない**（終了コード 2）。話題・範囲を広げる
- `braindex scope` は規則ベースの列挙・絞り込み・分割だけを行い、矛盾の判定はしない（それは次の手順）

### 2. chunk ごとにサブエージェントで敵対的に矛盾を探す

chunk 1 つにつきサブエージェント 1 体。委任プロンプトには次の 4 要素と幻覚対策の定型句を必ず入れる:

```
objective: 次のノート群の中の「相互矛盾」と「陳腐化」を、実ファイルを全文読んで洗い出す。
対象(実ファイルを読む。索引の 80 字要旨で判断しない):
  - <root>/<path>  「<title>」(<date>)   ※ -dir で出したときは <渡したディレクトリ>/<path>
  - …(この chunk のパス一覧)
探すもの:
  (a) 相互矛盾 = 同じ事実・指標について、2 つのノートが数値・結論で食い違う
  (b) 陳腐化   = 片方が古く、新しいノートや現状(コード・実データ)と食い違う
output format(蒸留結果だけ。生データはファイルに保存してパスを返す):
  各件 = { A: "path:line", B: "path:line", 対立点: "…", 新しい/正はどちら: "…(日付と、どちらが正本か)", 確信度: 高/中/低 }
tools と情報源: 各パスの実 .md を読む。数値・日付・固有名詞は本文で確認する。
task boundaries: この chunk のノートだけ。修正はしない(検出のみ)。他の chunk は別のエージェントの担当。
幻覚対策: 不確かなら「わからない」と書く。出典を出せない断定はしない。滑らかな自信を根拠にしない。
```

### 3. 各候補を反証する

集まった候補を、別の視点で潰しにかかる:

- 本当に両立しないか（スコープ・前提・単位・時期が違うだけではないか）
- 既に `decisions.md` 式の日付つき上書きで解消済みではないか（古い方が明示的に更新済みなら矛盾ではない）
- 数値の食い違いは、対象期間・母集団が違うだけの見かけの差ではないか

**反証役に結論を渡さない。** 反証をサブエージェントに委任するときは、2 つの生ノート（該当箇所）と突き合わせ条件だけを渡し、
手順 2 が付けた「矛盾している／B が正」という判断は伏せる。結論を渡すと反証役が追認の方向に歪む。
「この 2 記述は両立するか、しないならどこがどう衝突するか」だけを独立に判定させ、手順 2 の候補と食い違ったら、
その不一致自体を情報として扱う（手順 2 の偽陽性の印かもしれない）。

反証が 2 巡以上「指摘は出るが対応できるものがゼロ（全部却下か全部素通し）」なら、反証が形骸化している印。範囲・渡し方・粒度を見直す。

生き残った候補だけを残す。

### 4. 報告と振り分け

確信度の高い順に一覧にする。各件に **2 箇所・対立点・推奨する解決** を付ける:

```
contradiction-scan: <mode>   矛盾 <n> 件(反証後)

1. [高] <話題>
   A: <path:line>  「…」(YYYY-MM-DD)
   B: <path:line>  「…」(YYYY-MM-DD)
   対立: <何がどう食い違うか>
   推奨: <新しい B を正とし A を日付つきで上書き / 1 か所へ統合 / 実データで確認>
```

- 振り分け: 同じ事実の重複 → **1 か所へ一本化**（同じ事実を複数の場所へ書き写さない）／決定の食い違い → **`decisions.md` 式に日付つきで上書き**
  （消さず理由を添える）／陳腐化 → 日付つきで更新
- **自動編集はしない。提案する。** 実際の修正は確認のうえ個別に（必要なら `record-lint` で保存前に検査する）

## 注意

- 索引は対象の列挙源にすぎない。判断は必ず実ファイルの全文で行う（長いノートは先に該当箇所を引用抽出してから）
- 委任では蒸留結果だけを親へ返させ、生データはファイルに保存してパスで受け取る（親の文脈を汚さない）
- 完全にローカルで処理する。ノート本文・索引を外部に送らない
- これは**横断の矛盾検査**。1 ノート単体の曖昧さ（出典なき数字・曖昧な数量詞など）は `record-lint`
