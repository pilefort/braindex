# braindex news — ニュースサジェスト

[← README](../README.md) ／ [手引きの目次](README.md)

hub で `braindex news fetch` を実行すると、`news/feeds.json` のフィードを GET し、既読（`news/.seen.json`）に無い記事を
`news/digest_<日付>_<層>.md`（記録用）と、同名の `.html`（選別 UI・既定ブラウザで開く）に書く。
記事は関心プロファイルで採点し、関心度が `news.show_min_score`（既定 2）以上を主要表示、未満は「ほかの記事」に折りたたむ。
HTML の「選択と相談を保存」（旧「選別を書き出す」）が保存した JSON を `braindex news apply` が取り込み、「残す」を `news/keep/YYYY-MM.md` に追記する。
keep は次のプロファイルの出典になるので、**選別がそのまま関心の推定に戻る**。
外へ出る通信はフィードの GET と、有効にした場合の LLM 補助の呼び出し。セッション本文もノート本文も送らない。HTML は外部の JS・CSS を参照しない。
フィードのリンクは `http(s)` のものだけを載せる（それ以外は題名だけを出し、選別 JSON にも `news/keep/` にも入れない）。

フィード一覧 `news/feeds.json` は自分で作る。`braindex init`（news は既定で入る。外していたら `-add news`）は隣に `news/feeds.example.json`（公開フィード 3 件の見本）を置くので、
コピーして書き換える。`braindex news` が画面の候補から取材先を足すこともある。既存の行は触らず、整形を保って末尾に足す。
`name` と `url` を持つオブジェクトの配列:

```json
[
  { "name": "Go Blog", "url": "https://go.dev/blog/feed.atom", "layer": "weekly", "lang": "en" }
]
```

`layer` は自由なラベル（`daily`・`weekly` など）で、`news fetch -layer <層>` の絞り込みと表示上限（`cap_per_layer`）に使う。
空のフィードは `-layer all`（既定）のときだけ取る。`lang`・`category`・`note` は任意。未知のキー・`name` の重複・
`http(s)` でない URL はエラーにする。RSS 2.0・Atom・RSS 1.0 を読み、記事の識別子は追跡パラメータを除いたリンクから作る
（同じ記事が `utm_` 付きで再配信されても既読と一致する）。

サブコマンド:

| サブコマンド | 何をするか |
|---|---|
| `news fetch` | フィードを取得し、新着のダイジェスト（Markdown）と選別 UI（HTML）を書く。冒頭で `apply` と同じ取り込みも動く |
| `news profile` | 関心プロファイル（語 → 重み・出典）を表示する。出典は索引の直近差分（索引の隣に本文の変更の記録 `index/changes.json` があれば、記録日が古くても本文を直したノートを観測日で数える）・直近のセッション内容・`news/keep/`・`news/interests.md` |
| `news apply` | 選別 JSON を `<news.dir>/inbox` と `-inbox`（既定 `~/Downloads`）から取り込む |
| `news overview` | 会話で書いた概要の Markdown を、記事ごとに仕分けできる HTML にして開く（詳しく知りたい／概要で足りた／興味なし。詳しく知りたい分の相談文をまとめて作れる） |
| `news reading` | 日付をまたぐ保存記事と解説を開く。`-pending` で未回答の相談、`-id` と `-question` で相談文を表示。`-answer FILE` で会話で作成した回答を登録する |
| `news suggest` | 直近の会話・索引・keep から作った関心プロファイルに当たる取材先（RSS）を、同梱の取材先目録（17 ジャンル・98 本）から候補として出す。`feeds.json` に登録済みのものは除く。`-top N`（既定 10）・`-json` |

重みは出典ごとに最大を 1 に正規化した値の和で、規則ベース。LLM 補助が有効なら、その採点を重ねる。窓の起点は `retro` と同じローカルの 0 時。
数えるセッションの範囲も `retro` と同じで、既定は `root` 配下だけ（設定 `retro.all_projects` か `-all-projects` で全部。→ [retro.md](retro.md#数えるセッションの範囲)）。
主なフラグ: `-config` `-date YYYY-MM-DD` `-layer` `-out` `-stdout` `-no-open` `-no-score`（採点せず全件を主要表示）`-no-llm`
`-replay`（既読を無視して再生成し、既読も更新しない）`-days` `-top` `-json` `-sessions` `-inbox`。
終了コード: 0 成功／1 失敗（**同じ日の出力先が既にある**・`-out` と `-stdout` の同時指定・別の `braindex news` が動いている・全フィードの取得失敗。何も書かない）／2 警告つきで完了（一部のフィードが取れなかった・採点の出典が無かった・選別や統計を取り込めなかった・LLM 補助が呼べなかった・残留したロックを外した・別の日の未完了が残っている）。
同じ日に 2 回動かすと、既にあるダイジェストは上書きせず終了コード 1 で止まる（`braindex review` と同じ。読み直すだけなら `-out` で別名に、捨ててよければ `-stdout` に出す）。
`-out` と `-stdout` は同時に指定できない（`-stdout` はファイルに書かないので `-out` が使われずに黙って無視されるのを避けるため、終了コード 1 で拒否する）。
例外は前回が途中で止まった日で、もう一度実行すると書き直して既読まで進める（→ 下の「途中で止まったとき」）。

**設定例**（全部省略可。`init` が news 節を新しく書く際は、PATH に `claude` があれば `llm` を `claude-cli` にする。既存の節は変更しない）:

```json
"news": { "dir": "news", "feeds": "news/feeds.json", "seen_days": 90, "profile_days": 14, "serendipity": 2,
          "cap_per_layer": { "daily": 15, "weekly": 25, "general": 5 }, "show_min_score": 2,
          "llm": "off", "llm_model": "", "llm_timeout_sec": 120, "llm_budget_sec": 600 }
```

| LLM の設定キー | 既定値 | 意味 |
| --- | --- | --- |
| `llm` | `off`（省略時） | `claude-cli` で訳と採点を有効にする。`init` は PATH に `claude` がある場合だけ有効で作る |
| `llm_model` | 空文字 | CLI の既定モデルを使う |
| `llm_timeout_sec` | 120 | 1 回の呼び出しの上限（秒） |
| `llm_budget_sec` | 600 | 再試行を含む LLM 補助全体の上限（秒）。超えたら残りは呼び出さず語の点で出し、警告・終了コード 2 にする。0 は既定値 |

リンクのない記事は、フィード URL と題名で見分ける。2026-09-13 の方式変更後、以前の既読記事が一度だけ再表示されることがある。
概要を平文にしたとき、空でない行がすべて `Article URL:`・`Comments URL:`・`Points:`・`# Comments:` で始まる行か URL だけの行なら、概要を表示せず、LLM にも渡さない。普通の文を含む概要は残す。

**もしかして興味あるかも（関心外からの拾い上げ）**: 関心度が `show_min_score` 未満で「ほかの記事」に落ちた記事から、
`serendipity` 件（既定 2・0 で止める）を独立した枠に出す。関心度が高い方（1）から選び、1 つのフィードから 2 件は選ばない。
並びは「日付＋記事 ID」で決まるので、同じ日に何度作り直しても同じ記事になり、日が変われば入れ替わる。
拾い上げた記事は「ほかの記事」からは外れる。あとで読むに入れると、これまでどおり関心プロファイルに反映される。

**概要の画面（`braindex news overview`）**: 選別が終わったあと「まとめて概要を頼む」で受け取った概要を、記事ごとに
仕分ける画面。会話で書いた Markdown を渡すと、記事ごとに「詳しく知りたい／概要で足りた／興味なし」を選べる HTML にする。
記事の区切りは `<!--braindex-article id=記事ID question=相談ID link=URL-->` の行で、区切りが無ければエラーにする
（黙って 1 件にまとめない）。下部に「N 件中 M 件を仕分け済み」が出るので、長い概要でもどこまで読んだかが分かる。
「詳しく知りたい分を頼む」を押すと、その記事だけの相談文が出る。相談文の登録コマンドは `news reading -id <記事ID>
-ask detail -answer <回答ファイル>` で、`-ask` は相談を新しく作ってから回答を登録する（概要の画面は選別 JSON を
書き出さないので、相談を作る口がコマンド側に要る）。仕分けはブラウザに残るので、開き直すと続きから読める。

**置き場 `news/`**: `feeds.json`（自分で書く）・`keep/YYYY-MM.md`（残した見出し。蓄積側なので版管理に残す）・`interests.md`（任意の補助）が利用者のもの。
`digest_*`・`.seen.json`（既読）・`.stats.json`（選別の統計）・`.llm_cache.json`・`.ingested/`（取り込み済みの選別 JSON）・
`.lock.json`（動いている印）・`.pending.json`（途中で止まった回の記録）は作業ファイルで、`braindex init`（news は既定。外していたら `-add news`）が hub の `.gitignore` に足す行が除外する。

**補助ファイル `news/interests.md` の書き方**: 1 行 1 語。空行と `#` 始まりは読まない。行は記事側と同じ語の抽出規則（ラテン文字 3 字以上・カタカナ 2 字以上・漢字 2〜6 字。
大文字小文字は畳む）を通してから語にするので、**規則で語にならない書き方（`ai`・`go` のような 2 字のラテン文字、記号だけ、長い漢字の複合語）は記事側でも語にならず、
表に重みつきで並んでも照合には効かない**。`braindex news profile` の表で `extra` 列に載っている語が、記事の見出しに現れる形と同じかを確かめる。
`|` を含む行は表の描画を崩すので書かない。

**LLM 補助**: `"llm": "claude-cli"` にすると、`claude` CLI（PATH にあるもの）をヘッドレスで呼び、英語見出しの日本語訳と関心度 0〜3 を受け取って
語の一致の点に重ねる（バッジの説明とダイジェストに `LLM` と出る）。渡すのは見出し・概要・言語・関心プロファイルの語・keep の見出しだけで、リンク・セッション本文・
ノート本文は渡さない。結果は `news/.llm_cache.json` に記事 ID で覚え、同じ記事を 2 回聞かない。`llm_model` で `--model` を指定できる（空なら CLI の既定）。
1 回に聞くのは 10 件まで。**日本語でない記事なのに訳が返らなかったときは、その記事だけを 5 件ずつでもう一度聞く**（1 回だけ。進捗に
「訳が返らず N 件を聞き直し」と出る）。2 度目も空なら記事に `nt` の印を残し、次回からは聞かない——毎回聞き直すと費用だけが増えるため。
CLI が無い・`llm_timeout_sec` を超えた・応答が JSON でないときは警告（終了コード 2）にして、その記事は語の点のまま出す。`-no-llm`（と `-no-score`）で止まる。
`claude` は `--tools ""` で起動し、道具は一切使わせない。記事の見出し・概要は `<articles>` の区切りに入れて渡し、その中の指示に従わないよう明示する
（渡すもの＝見出し・概要・言語・語・keep の見出し／許すこと＝翻訳と 0〜3 の採点だけ）。フィードは他人が書いた本文なので、そこに指示を埋めても採点は動かない。

**定期実行**: `braindex init` が `schedule.jobs` に次の job を入れる（時刻は `braindex.json` で直す）。登録は `braindex schedule install`（仕組みは [schedule.md](schedule.md)）:

```json
{ "name": "news", "args": ["news", "fetch", "-layer", "daily", "-no-open"], "when": "daily:07:30" }
```

`-no-open` なのは、cron・schtasks から起動したプロセスがログイン中のデスクトップにウィンドウを出せないため。朝に `news/digest_<日付>_daily.html` を自分で開く。
**選別の保存先**: 「選択と相談を保存」を押すと保存ダイアログが出る（Chrome・Edge）。**初回は hub の `news/inbox/` を選ぶ**と、
2 回目からは同じ場所が既定になる（`id` でディレクトリを覚えるため）。`news fetch` が `news/inbox/` を先に作っておくので、
ダイアログでそのまま辿れる。Firefox と Safari は保存ダイアログに対応していないので、従来どおりダウンロード先に落ちる。
ダイアログを閉じただけのときは何も書かず、ボタンの文字も戻る。
`file://` で開いた HTML でもダイアログは出る（実測 2026-09-06 → `docs/notes/common/file-url-save-picker.md`）。

選別を書き出した JSON は次回の `fetch` か `braindex news apply` が拾う。

**取り込みは中身を検査する**: 選別 JSON はブラウザのダウンロード先（誰でも置ける場所）から拾うので、そのまま信じない。
`date` が `YYYY-MM-DD` の形でないファイルは取り込まず、`.ingested/` へも移さない（中を見て消せるように元の場所に残す）
——`date` は `news/keep/YYYY-MM.md` のパスの一部になるため。`feed_stats` は `feeds.json` にある取材先の名前で、数が 0 以上の項目だけを数え、
外れた項目は落として 1 行で伝える。1 件も取り込めなかった回は `.stats.json` を触らない。

**途中で止まったとき**（2026-09-06 追加）: `fetch` はダイジェスト md → 選別 UI html → 既読の順に別のファイルを書く。
電源断やディスクの空き不足で途中で止まると「md はあるのに既読が進んでいない」のような食い違いが残るので、書き始める前に
`news/.pending.json` へ出力先を記録し、既読まで書けたら消す。**立て直しは、同じ日の `fetch` をもう一度実行するだけ**——記録にある出力先は
まだ書き終えていない回のものなので「既にある」で止めず、フィードを取り直して書き直し、既読まで進める（完了した回はこれまでどおり上書きしない）。
別の日の未完了が残っていれば警告（終了コード 2）で伝える。その回に出た記事は既読に入っていないので、次の回にも新着として出る（消えはしない）。
完了させるには、表示されるコマンド（`braindex news fetch -date <日付> -layer <層>`）を実行する。要らなければ `.pending.json` からその記録を消す。
選別の取り込みには記録が要らない。JSON 1 つごとに keep → 統計 → 取材先の登録 → 読書 → `.ingested/` へ移す、の順に書くので、どこで止まっても次回は
同じ JSON を読んで同じ結果に揃う（keep は同じリンクを 2 回足さない・統計はダイジェスト単位の上書き）。
**並行起動**（定期実行と手動が重なったとき）は `news/.lock.json` で片方だけにする。2 つ目は何も書かずに終了コード 1 で止まる（`apply` も同じ）。
前の実行が途中で落ちてロックが残ったとき（残留）は、1 時間より古ければ外して警告（終了コード 2）つきで進む。それより新しい残留は、
動いている `braindex news` が無いことを確かめて `.lock.json` を消す（メッセージに場所が出る）。

**不要ばかり付く取材先は下げる**（2026-09-06 追加）: `.stats.json` の累計で「残す／不要を選んだ数」が 10 件以上、
そのうち不要が 80% を超える取材先は、次回から関心度の上限を 1 に下げる（主要表示から折りたたみ側へ回る）。
不要率は「見た数」でなく「選んだ数」で割る——折りたたみに入って目に入らなかった記事を不要と数えないため。
承知のうえの代償が 1 つある: いったん下がると `keep` に入りにくくなるので、不要率が下がる機会も減る。
完全に読まなくなった取材先は `feeds.json` から消す（間引き候補として `news fetch` が出す）。

**取材先の候補（`braindex news suggest`）**: 何を `feeds.json` に書けばよいか分からないとき、直近の会話で使っている技術から取材先を探す。
同梱の目録の各取材先が持つ照合語（例: Docker Blog → `docker` `dockerfile` `compose` `コンテナ`）と関心プロファイルの語を手元で突き合わせ、
当たった語の重みの和が大きい順に出す。照合は手元だけで、通信も LLM もしない。出力は当たった語と数だけで発話の本文は載せない。
候補を採るときは、`news fetch` の選別画面で候補欄を開き、1 本ずつ「追加する」を選ぶ。
「選択と相談を保存」で JSON を保存し、`news apply` または次の `news fetch` で登録する。
`fetch` の冒頭で追加した取材先は、その次の `fetch` から取得する。出力の URL を `feeds.json` に手で書いてもよい。
候補は毎回折りたたんで 3 件まで出す。見送った候補は覚えない。検索語の候補も別に 3 件まで出す。
`-no-score` または関心プロファイルが空の場合は候補を出さない。`-stdout` の Markdown にも候補を記録する。
照合語は作者が付けた分類で、当たり方が外れることがある。`braindex news profile` で自分の語を見て、`interests.md` に語を足せば当たりを寄せられる。

## 記事を選び、解説を読む

画面上部の分野から記事を絞れます。記事は見出し、概要、操作の順に表示します。日本語訳がある場合は先に表示し、
原見出し・原概要・採点の理由を展開して見比べられます。訳がない記事は原文のままです。概要がない場合は、概要欄を表示しません。
新しい解説や要約を自動生成する処理は追加していません。翻訳・採点は `news.llm` の設定に従います。

- **あとで読む**: その場で一覧へ追加します。取り込み前の選択は取り消せます。
- **今回は見送る**: 「見送った記事」に移します。そこから戻せます。不要の評価として記録する操作です。
- **読了・保留・試したい**: 保存対象の記事ごとに選べます。分からないことや保留を、不要の評価には数えません。
- **解説してもらう**: 「ざっくり」「原文・解説を読んでも分からない」「自分との関係」「試す方法」から選び、相談文を作れます。
  どこが分からないか書けなくても相談できます。同じ記事の以前の質問と回答を相談文に含めるので、続きを聞けます。
- **まとめて概要を頼む**: 「あとで読む」に入れた記事の分だけ、概要を頼む相談文を 1 つにまとめます。相談文には記事ごとの
  登録コマンドが並ぶので、回答は記事ごとに登録できます。概要の回答は 1 枚にまとめて返してもらい、詳しい解説は記事ごとに
  1 枚で返してもらう取り決めです（`docs/decisions.md` 2026-09-07）。
- **読む状態で仕分ける**: 概要を読んだら、記事ごとに「詳しく知りたい」「概要で足りた・読了」「興味なし」などを選びます。
  「あとで読む」のまま残っている件数が一覧の右上に「まだ仕分けていない N 件」と出るので、どこまで見たかが分かります。
- **詳しく知りたい分を頼む**: 「詳しく知りたい」にした記事だけを集めて、詳細の相談文を 1 つにまとめます。回答は記事ごとに
  1 枚の HTML で、上から順に返ってきます。

選択と相談はブラウザ内の下書きです。「選択と相談を保存」でファイルに書き出し、`news apply` または次回の `news fetch` で取り込みます。
保存ダイアログを取り消すと下書きは残ります。書き込みに失敗した場合は成功と表示しません。
ダウンロード方式では保存完了をブラウザから確認できないため、「ダウンロードを開始」「取り込みは未確認」と表示します。
保存後に状態を変えた場合は、再保存の必要を表示します。

日付をまたいだ一覧は、ダイジェストの「日付をまたいで、保存した記事を読む」か、次のコマンドで開きます。

```text
braindex news reading
```

`news/reading.html` は取り込み済みの記事・読書状態・相談・回答を表示します。古いHTMLは自動更新されません。
取り込みや回答登録の後に一覧を開き直してください。取り込み済みの記事は履歴として保持し、「読了」「保留」で整理します。
導入前の記事も、残っている `news/.ingested/` の選別JSONから復元します。選別JSONが無く月別Markdownだけが残っている記事は自動復元しません。

## 解説を依頼し、同じ記事に回答を残す

相談文のコピーは送信ではありません。利用者がCodexやClaude Codeなど、相談したい会話に貼り付けて送ります。
HTMLからエージェントを自動起動したり、記事や相談を外部へ自動送信したりしません。
記事への登録に備えて「選択と相談を保存」も行い、先に取り込みます。

```text
braindex news apply
braindex news reading -pending
braindex news reading -id <記事ID> -question <質問ID>
```

`-pending` は回答がまだ登録されていない相談の一覧です。処理中や送信済みという意味ではありません。
`-id` と `-question` は、その記事のURL・質問・以前のやり取りを含む相談文を出します。
相談文は本文の確認と、記事の主張・確認できた事実・推測の区別を求めます。本文を取得できなかった場合は、その旨を回答に残します。

回答担当は解説をローカルのMarkdownに保存し、相談文に記載されたIDで登録します。登録後、保存記事の一覧が開きます。

```text
braindex news reading -id <記事ID> -question <質問ID> -answer answer.md
```

既存の回答は上書きしません。同じ内容の再登録は安全に再実行できます。訂正や追加の説明は、画面から追加質問を作って登録します。
登録後はボタンが「解説を読む」に変わり、同じ画面からさらに質問できます。回答は安全なテキストとして表示します。
理解できたら「読了」、試すなら「試したい」、今は扱わないなら「保留」を選び、変更を保存します。

`-no-open` でブラウザを開かずに一覧を更新できます。`reading` も `fetch`・`apply` と同じロックを使います。
記事・相談・回答の正本は `news/.reading.json` です。ブラウザの保存領域やHTMLとは別のローカルファイルで、
既存の `news/.*.json` の除外規則によりgitへ入りません。相談と回答を残すには、このファイルもバックアップ対象にしてください。
壊れた正本は空の内容で上書きせずエラーにします。古い選別を取り込み直しても、登録済みの回答と新しい読書状態は消しません。

## 検索フィード

検索語の候補は、関心語のうち取材先の目録の照合語に無く、検索フィードとしても未登録の語から、重みの高い順に出す。
候補の生成は手元で行い、通信しない。ニュース収集で Google News に送るのは、画面で「追加する」を選び、保存した JSON から登録した語だけ。
名前は「検索: <語>」、分類は「検索」になる。登録後は普通のフィードと同じ GET で取得する。

URL は `https://news.google.com/rss/search?q=<URL エンコードした語>&hl=ja&gl=JP&ceid=JP:ja`。
地域は語の文字種で決める（推測に基づく規則）。ASCII だけの語なら末尾を `&hl=en-US&gl=US&ceid=US:en` にし、それ以外は日本向けにする。
地域ごとの RSS 応答は、この実装時には通信して検証していない。

## 一般ニュースの層

候補から登録した一般ニュース（日本・海外）は、画面の層に関わらず `general` 層へ入る。
`cap_per_layer` を省略した場合は `daily: 15`・`weekly: 25`・`general: 5`。いずれも 1 フィードあたり、主要表示・折りたたみの各段の上限。
`cap_per_layer` を書いたら、その表が正で、既定の表とは合成しない。既存設定にも `"general": 5` を明示するとこの上限が効く。
表に無い層（`all` を含む）は従来どおり 20 件。`-layer all` では `general` の 5 件を個別には適用しない。

5 件という値は推測。調査「research-news-review-2026-09-13.md」A4 の一般ニュース 1 日 74 件を、5 本 × 5 件 = 25 件程度に抑える見当で決めた。
調査では 1 フィードあたり 1 日 7〜35 件、NHK 国際は初回 128 件が新着になるため、専用の層で量を調整する。
`-layer daily` の定期実行では一般ニュースを取れない。定期実行に `-layer general` の行を足すか、`-layer all` で取る。

取材先の登録に失敗したときは、その JSON を取り込み済みへ移さない。keep と統計は先に反映される。
`feeds.json` が無ければ作成し、壊れている場合や書けない場合は直してから再実行する。同じ URL・keep のリンク・統計を二重に足すことはない。

## 決めたこと

- **途中で止まった回の立て直しは「同じ日の `fetch` をもう一度実行する」だけにし、立て直しのコマンドは足さない。** 記録（`.pending.json`）にある
  出力先だけを「まだ書き終えていない」と見分けて書き直す。「同じ日は上書きしない」（決定 2026-09-03 → 下の「決めたこと」）は完了した回に対して保つ
- **記録は「無いのが普段の状態」にする。** 書き始めに置いて、既読まで書けたら消す。出力先ごとに完了の印を置く案は、普段から
  ファイルが増えるので採らない
- **書く順は md → html → 既読。ブラウザは最後に開く。** 既読を先に書くと、ダイジェストを書けずに止まったとき新着が消える。
  保存物を全部書いてからブラウザを開くので、開くのに手間取っても・そこで止められても食い違いは残らない
- **立て直しは前回の出力を使い回さず、フィードを取り直して書き直す。** 前回の md と既読を突き合わせて足りない分だけ書く案は、フィードが
  その間に変わっていると md・html・既読が別々の内容になる。書き直せば 3 つが同じ取得結果から出る
- **選別の取り込みは記録を持たず、書く順序で揃える。** JSON 1 つごとに keep → 統計 → 移す、の順。逆（移してから統計）だと、移した後に統計を
  書けずに止まったとき、その選別の数は二度と拾えない（置き場から消えているので次回は読まない）
- **ロックの残留は時間で判定する（1 時間）。** プロセス番号（PID）の生存確認は OS ごとの実装が要り、番号の再利用で誤る。1 時間は、LLM 補助が
  全バッチで待ち時間いっぱい（既定 120 秒。1 回に聞く件数は決定時 20 件、2026-09-07 から 10 件。2026-09-13 からは全体の上限 `llm_budget_sec` 600 秒が先に効く）かかっても 1 回の `fetch` が収まる長さ。それより新しい残留は手で消す
- **`apply` の終了コードは 0／1 のまま。** 残留したロックを外したときは警告を出すが 2 にはしない（`apply` は 2 を持たない）
- **作業ファイルの名前は `news/.*.json` に揃える。** hub の `.gitignore` にある既存の行がそのまま除外するので、配布テンプレを変えない

### 選別 HTML の保存ダイアログは実装する（`file://` でも開くことを実測した）

### ニュースの複数ファイルにまたがる保存は、未完了の記録（`news/.pending.json`）とロック（`news/.lock.json`）で立て直す。「同じ日は上書きしない」は完了した回にだけ効かせる

記録日: 2026-09-06
理由: `news fetch` は md → html → 既読の順に別のファイルを書くので、1 ファイルずつ原子的でも途中で止まると「md はあるのに既読が進んでいない」が残り、次の実行は「既にある」（2026-09-03）で止まって手が出せなかった。書き始める前に出力先を記録し、既読まで書けたら消す。こうすれば記録にある出力先だけを「まだ書き終えていない」と見分けて書き直せ、規則は完了した回に対して保てる。並行起動（定期実行と手動）は取り込みが同じ keep を 2 回足すので、ロックで片方だけにする。選別の取り込みは JSON 1 つごとに keep → 統計 → 移す、の順にすれば記録を持たずに再実行が揃うので、記録は `fetch` だけに持たせる。却下: 既読を先に書く（ダイジェストを書けずに止まると新着が消える）／出力先ごとに完了の印を置く（普段からファイルが増える。無いのが普段の状態になる記録のほうが軽い）／プロセス番号（PID）の生存確認で残留を判定する（OS ごとの実装が要り、番号の再利用で誤る。時間で判定し、1 時間より新しい残留は手で消す）／立て直しのコマンドを足す（同じ日の `fetch` をもう一度実行するだけで足りる）。
根拠: 設計レビュー補足 2026-09-06「同時実行と中断後の再実行を機能単位で設計する」（`docs/notes/project/design-review-addendum-2026-09-06.md`）／挙動の取り決めは `manual/news.md` の「途中で止まったとき」と「決めたこと」／実装は `internal/news/run.go`（ロック・記録）と `internal/news/apply.go` の `Ingest`（順序）、流れは `cmd/braindex/cmd_news.go`（PR `codex/dr-news-recovery`）／再現は `cmd/braindex/cmd_news_recovery_test.go`（既読の保存を失敗させる・html の場所を塞ぐ、の 2 通りで止めてから同じ日を再実行して完了すること、並行起動で片方だけ書くこと、残留ロックの回復）と `internal/news/apply_test.go`（統計の保存を失敗させて再実行で揃うこと）。旧コードでは、再開のテストが「未完了の記録が無い」「再実行が『既にある』で終了コード 1 になる」で、取り込みのテストが「移した後に統計が無い」で落ちるのを確認した（2026-09-06）
