# 内容の種別 — 失敗・手順・観測でノートを引く

[← README](../README.md) ／ [手引きの目次](README.md)

内容の種別は本文の先頭 10 行以内に、任意で 1 行だけ書く。未記入のノートも使える。

```markdown
# 起動時の落とし穴

記録日: 2026-09-13
種別: 失敗
結論: 設定を直すと起動できた。
```

本文の値は **失敗・手順・観測** の 3 語。コロンは `:`／`：`、前後の空白はどちらも許す。
コードフェンスの中は読まない。BOM・CRLF のノートも読める。
「決定」は内容の種別に含めず、`docs/decisions.md` に書く。
索引の 2 列目と `search -kind` は **置き場の種別**（`notes/project` など）で、内容の種別とは別。
索引は 5 列のままで、要旨には `種別:` 行を拾わない。

## 既存ノートに付ける

```sh
braindex type suggest -out candidates.md
# candidates.md を読み、採用する行を [x] にする。種別の列も直せる
braindex type apply candidates.md -dry-run
braindex type apply candidates.md
```

`suggest` は索引と同じ走査規則で列挙し、置き場の種別が `decisions` のファイルと、種別が記入済みのノートを除く。
タイトルとファイル名の語を、失敗・手順・観測の語表に部分一致で当てる（大小無視）。本文の意味は推定しない。
1 軸だけ当たればその値、複数の軸なら「未定」と当たった軸を出す。どの軸にも当たらないノートは件数だけを出す。
候補はパス昇順。通信と LLM は使わない。不正な種別行や読めないファイルは警告して飛ばす。

```text
- [ ] 失敗 | repo-a/docs/notes/x.md | 起動時の落とし穴 | 語: 落とし穴
- [ ] 未定（失敗・観測） | repo-a/docs/notes/y.md | 調査と失敗の記録 | 語: 失敗, 調査
```

`apply` は行頭が `- [x]`／`- [X]` の行だけを読む。最初の `|` より前が種別、その次が root 相対のパス。
種別には CLI の別名 `failure`・`howto`・`observation` も指定できる。本文には日本語を書く。
「未定」のままなら警告して飛ばす。同じ値があれば「そのまま」、違う値があれば置き換えずに警告するので、手で直す。
種別行が重複している場合や 11 行目以降にある場合も、手で直してから実行する。
パスとタイトルに含まれる `|` などは候補内で文字参照にし、読み込み時に戻す。

書き込みは記録日行の直後、無ければ最初の H1 の直後（次が空行ならその後）、H1 も無ければ 1 行目。
挿入先が 10 行以内に収まらなければ警告して飛ばす。元の改行コードと BOM を保ち、一時ファイルから置き換える。
結果は「書いた／そのまま／飛ばした（理由）」と末尾の件数。`-dry-run` は同じ結果を表示するが本文には書かない。
索引は書き換えない。次に `braindex` を実行すれば再生成でき、種別行を付けても要旨は変わらない。

| コマンド | フラグ |
|---|---|
| `type suggest` | `-config`・`-root`・`-repo 名`・`-out ファイル`・`-json` |
| `type apply <チェックリスト>` | `-config`・`-root`・`-dry-run` |

設定は既定でカレントの `braindex.json`。設定内の root は設定ファイルの場所が基準で、`-root` はカレントが基準・設定より優先。
`suggest` は `-out` が無ければ stdout に出す。既存の出力ファイルは上書きしないので、再生成するときは別名を指定する。
`-json` は候補の配列で、`path`・`title`・`candidate`（未定なら空文字）・`axes`・`terms` を持つ。`apply` に渡すのは Markdown のチェックリスト。
終了コードは 0 成功／1 引数・設定・候補の入出力の失敗／2 警告つき完了。走査の警告や反映できなかった行は stderr に出す。

## 内容の種別で絞る

```sh
braindex search -type 失敗 起動
braindex search -kind notes/project -type howto 設定
braindex search -type none 起動
braindex scope -full -type 手順
braindex scope -topic 設定 -repo repo-a -type 観測
braindex scope -dir ./docs/notes -type 失敗
```

両方の `-type` が失敗・手順・観測・未記入と別名 `failure`・`howto`・`observation`・`none` を受ける。
不正な本文の種別は警告して未記入扱い。CLI の値が不正なら終了コード 1。
`scope -type` は `-topic`／`-repo`／`-dir`／`-full` に追加する絞り込みで、単独では使えない。
索引から読むときは `-root` か設定の root が必要。`-dir` なら列挙したパスをそのまま開くので root は不要。
読めないノートも警告して未記入扱いとし、`-type none` なら残す。scope は警告あり、または対象が 2 件未満なら終了コード 2。
`-type` 指定時の scope は行末に `［失敗］` などを添える。未指定なら本文の種別を読まず、従来の Markdown 表示のまま。
scope の JSON は各行に `type` を持ち、未指定なら空文字。

`braindex lint <ノート>` は不正な値と 11 行目以降の種別行を warn にする。未記入は指摘しない。
hub の雛形の案内は `braindex update` で届く。編集済みの配布物には既存の台帳・`.new` の仕組みが適用される。

## 決めたこと

### 内容の種別は本文に書き、索引の列は増やさない

記録日: 2026-09-13
結論: 書き手が先頭に 1 行で書き、絞り込みは `search`／`scope` に足す。
理由: 5 列を読む既存の仕組みを保ったまま、内容の種別で引けるようにする。
根拠: `braindex-docs/docs/decisions.md` 2026-09-13「索引の内容の種別は、書き手が新しいノートの先頭に 1 行で書く（索引の列は増やさない）」。

### 失敗・手順・観測の 3 種と未記入にする

記録日: 2026-09-13
結論: 「決定」は種別に持たず、未記入も許す。
理由: 決定は `docs/decisions.md` の置き場で絞れる。
根拠: `braindex-docs/docs/decisions.md` 2026-09-13「索引の内容の種別は 3 種（失敗・手順・観測）＋未記入にする」。

### 既存ノートには候補を出し、承認した分だけ本文に書く

記録日: 2026-09-13
結論: タイトルの語から出した候補をチェックリストで承認し、推定を索引に書かない。
理由: 語による候補と書き手の判断を分け、反映前に差分を読めるようにする。
根拠: `braindex-docs/docs/decisions.md` 2026-09-13「既存のノートにも種別を付ける。braindex がタイトルの語から候補を出し、承認した分だけ本文に書く」。

### 索引の決定性を保つ

記録日: 2026-09-13
結論: 同じ入力なら生成日の行を除いてバイト一致する。
理由: 再生成の差分を内容の変化として読めるようにする。
根拠: 実装 SPEC 2026-09-13 の既決、および `braindex-docs/docs/decisions.md` 2026-08-07「索引の要旨は機械抽出にし、LLM を使わない」。
