# braindex search — 本文の検索と出典位置

[← README](../README.md) ／ [手引きの目次](README.md)

```sh
braindex search 決定性                 # 各リポのノート本文から語を含む行を「パス:行: 内容」で出す
braindex search 索引 決定性            # 両方の語を同じ行に含む行だけ
braindex search -any 索引 決定性       # どちらかの語を含む行
braindex search -repo alpha -kind decisions 決定性   # リポと種別で絞る
braindex search -type 失敗 起動         # 内容の種別が失敗のノートだけ
braindex search -type none 起動         # 内容の種別が未記入のノートだけ
braindex search -w go                  # go を google に当てない(ラテン文字の語の境界)
braindex search -json 決定性           # 機械可読(terms・files・total・hits・gaps・complete)
```

索引（`index/catalog.md`）は「パスを引く」ためのもので、要旨 80 字は手がかりにすぎない。索引に語が無いことは
本文に記録が無い証明にならないので、本文そのものを読んで語を照合し、当たった位置（ファイルと行）を出す。
索引と同じ走査規則（設定 `braindex.json` の `root`・`notes_dirs`・`extra`。`archive` の下は読まない）で対象を
列挙し、索引は読まない。本文は手元で読むだけで、外には何も送らない。意味検索・埋め込み・LLM は使わない。

## 出力

```text
# braindex search: 決定性（語を含む行・大小無視）
対象 42 ファイル・一致 3 行（2 ファイル）
alpha/docs/notes/design.md:40: 同じ入力からは常にバイト一致する。これを決定性と呼ぶ。
beta/docs/decisions.md:12: ## 索引の決定性を守る
beta/docs/decisions.md:15: 理由: 決定性が無いと差分が読めない。
確認できなかった範囲 1 件（この中に一致があるかは分からない）
- gamma/docs/notes/locked/ — permission denied
```

- 1 行目は検索語と条件、2 行目は対象（最後まで読めたファイル数）と一致の数。絞り込みがあれば「（リポ alpha・種別 decisions）」を添える
- 一致は 1 行 1 件「パス:行: 内容」。パスは索引と同じ `root` 相対、行番号は 1 始まり。同じ行に複数の語があっても 1 件。
  順はパス → 行番号で、同じ材料からは同じ順になる。長い行は一致箇所の周辺 200 文字だけにし、切った側に `…` を付ける
- **確認できなかった範囲**は、走査で列挙できなかったディレクトリ（末尾 `/`）と、開けない・途中までしか読めなかったファイル。
  この範囲にあるノートは読んでいないので、「一致なし」を「記録が無い」と読んではいけない。索引の先頭にある「走査:」の記録と同じ考え方
- 一致なしのときは、確認できなかった範囲の有無で文言が変わる：「走査した範囲は全部確認できた」か「無いとは言えない」

`-json` は `terms`・`any`・`match_case`・`whole_word`・`repo`・`kind`・`files`・`total`・`hits`（`repo`・`kind`・`path`・`line`・`col`・`text`・`terms`）・
`gaps`（`rel`・`dir`・`reason`）・`complete`・`warnings`。`col` は最初に当たった語の位置（1 始まり・文字数。元の行の先頭から）、
`hits[].terms` はその行に含まれていた検索語（渡した順）。`complete` は確認できなかった範囲が無いこと。

## フラグと終了コード

`-type` は[内容の種別](type.md)（失敗・手順・観測・未記入）で絞る。別名は `failure`・`howto`・`observation`・`none`。
先頭 10 行の `種別:` 行を読み、条件に合わないノートは対象ファイル数にも確認できなかった範囲にも数えない。
不正な値や重複した種別行は未記入として扱い、警告を出して終了コード 2 を返す。
`-json` の `type` は条件、`hits[].type` は本文の値（未記入なら空文字）。別名も日本語で出す。
従来の `-kind` は置き場の種別（`notes/project` など）で、`-type` と併用できる。

`-config`（設定ファイル。既定はカレントの `braindex.json`）`-root`（走査のルート。設定より優先）`-repo`（リポ名の完全一致）
`-kind`（置き場の種別の完全一致か「種別/」で始まるもの。`notes` は `notes/common` も含む）`-any`（どれか 1 語で当たり）
`-case`（大小を区別。既定は無視）`-w`（ラテン文字の語の境界）`-limit N`（先頭 N 行。0 で全件）`-json`。
語は位置引数で 1 つ以上（空文字は誤り）。`root` の解決は索引の生成と同じで、フラグ > 設定ファイル > 既定。
終了コード: 0 成功（一致なしも 0）／1 失敗（語が無い・`root` が無い・フラグの誤り）／2 確認できなかった範囲がある（結果は出す）。

## 決めたこと

- **語はそのままの文字列で照合し、正規表現は受け付けない。** 検索の目的は「あると知っているノートを引く」ことで、
  語の一致で足りる。正規表現は `grep` がある。意味検索は入れない（決定 2026-08-19）
- **複数の語の既定は「同じ行に全部」（AND）。** `grep a | grep b` と同じで説明が短い。1 語でも当たりにしたいときは `-any`。
  ファイル単位の AND は入れていない（行が出典位置なので、行に無い語を根拠にできない）
- **大小は既定で無視する。** 索引の `scope -topic` と同じ。かな・漢字には影響しない。全角・半角の揺れは畳まない
  （畳むと `col` が元の行とずれる。必要なら語を両方渡して `-any`）
- **`-w` の境界はラテン文字の語にだけ引く。** 英字・数字・`_`・`-` の並びを 1 語とみなす（関心抽出の識別子の規則と同じ）。
  かな・漢字は連続して書かれるので境界を引けず、「全索引化」の中の「索引」や「ベクトルデータベース」の中の「ベクトル」は
  語の一致として扱う。学習候補の本文照合のように「その語について書いたか」を見る用途では、この扱いのほうが取りこぼしが少ない
- **確認できなかった範囲は結果に含め、終了コードは 2 にする。** 一致なしと区別するため。索引の「走査:」の記録（決定 2026-09-06 → [generate.md](generate.md)「決めたこと」）と同じ理由。
  読めなかったファイルが 1 つあっても残りの結果は出す（1 ファイルの権限エラーで検索全体を止めない）
- **索引は読まない。** 索引は生成日時点の写しで、本文の検索に使うと再生成前のノートを見落とす。走査規則だけを共有する
- **先頭 10 行で内容の種別を読み、その後は 1 行ずつ読む。** 1 行が数 MB あっても落ちない。`bufio.Scanner` は行の長さに上限があるので使わない
- 既存 TODO の `braindex grep`（索引の grep のラッパ）とは別物。あちらは索引の行、こちらは本文を読む

### 本文の検索（`braindex search`）は索引を読まず、索引と同じ走査規則で本文を 1 行ずつ読み、語の一致で出典位置（パス:行）を返す。確認できなかった範囲を結果に含め、「一致なし」と区別する

記録日: 2026-09-06
理由: 索引は「パスを引く」ための手がかりで、要旨 80 字に無い語が本文の後半にある。索引を grep して無いことを「記録が無い」と読むと、設計の保証を超えて不存在の証明に使うことになる。そこで本文そのものを読む `braindex search` を足す。索引は読まない——索引は生成日時点の写しで、本文の検索に使うと再生成前のノートを見落とす。走査規則（`root`・`notes_dirs`・`extra`・`archive` 除外）だけを索引と共有する。読めなかった範囲は結果に列挙して終了コード 2 にし、「一致なし（走査した範囲は全部読めた）」と「無いとは言えない」を分ける。語はそのままの文字列で照合し、正規表現は受けない（`grep` がある）。意味検索・埋め込み・LLM は入れない（決定 2026-08-19・2026-08-07 の範囲で足りる）。却下: 索引の要旨を長くする（索引の diff が重くなり、それでも本文全部は載らない）／読めない範囲があれば検索を止める（1 ファイルの権限エラーで検索全体を失う。索引の生成と同じ理由）。
根拠: 設計レビュー補足 2026-09-06「索引に語がないことと、本文に記録がないことを分ける」（`docs/notes/project/design-review-addendum-2026-09-06.md`）／実装は `internal/textsearch`（`Run`・`Result.Complete()`）と `cmd/braindex/cmd_search.go`、挙動の取り決めは `manual/search.md`「決めたこと」（PR #13（控え: pr/13.md）8（控え: pr/138.md））／読めなかった範囲の扱いは決定 2026-09-06「索引は走査で読めなかった範囲を先頭に記録」と同じ／学習の提案の本文照合（PR #14（控え: pr/14.md）1（控え: pr/141.md））がこの検索処理をそのまま呼ぶ
