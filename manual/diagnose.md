# braindex diagnose — 走査状態の診断

[← README](../README.md) ／ [手引きの目次](README.md)

索引（`index/catalog.md`）に行が無いことは「ノートが無い」証明にならない。読めなかった範囲のノートは載っていないだけで、
あるかどうかは分からない。設定を変えた・`archive/` へ移した場所の行も、削除ではない。`braindex diagnose` は、
**いま何を見に行き（設定）、いま何が読めて（走査）、保存済みの索引がどこまで追いついているか（索引）** を分けて示し、
「索引に無い理由」を人が自分で確かめられるようにする。索引も元ノートも書き換えない。

```sh
braindex diagnose                                  # hub で。設定 braindex.json と index/catalog.md を使う
braindex diagnose -path alpha/docs/notes/x.md      # このパスが対象か・いま見つかるか・索引に載っているか
braindex diagnose -json                            # 同じ内容を JSON で
braindex diagnose -root ../repos -catalog old.md   # 設定ファイル無しで、別の索引と突き合わせる
```

## 出力

先頭の「まとめ」だけ読めば、要確認があるかどうかが分かる。

| 節 | 中身 | 情報源 |
|---|---|---|
| まとめ | 問題なし、または要確認の理由の一覧（終了コード 2 の根拠） | 下の 3 節 |
| 設定（情報源） | 使った設定ファイル・root（絶対パス）・`notes_dirs`（既定かどうか）・`extra` の各規則と起点の状態（あり／存在しない／読めなかった／ディレクトリでない／archive の下）と、その起点の下で索引に載る件数 | `braindex.json`・フラグ |
| いま走査すると | この瞬間に索引を再生成したら載る件数、読めなかった範囲（ディレクトリは末尾 `/`）、それ以外の警告（存在しない `extra` など）、root 直下のリポ別の件数・種別・置き場の状態（ノートが無いリポは全部の置き場、あるリポは問題のある置き場だけ） | 索引の生成と同じ走査（`catalog.Build`） |
| 保存済みの索引 | 場所、状態（無し／読めない／braindex の形でない／生成日と件数）、先頭の走査の記録（読めなかった範囲なし／記録なし／N 件）、いまの走査との差 | `index/catalog.md`（読むだけ） |
| パス（`-path` のとき） | いまの設定で対象か（当たった規則、または対象外の理由）／いま走査すると見つかるか（見つかる・読めなかった範囲の中・見つからない）／保存済みの索引に載っているか | 上の 3 節 |

いまの走査との差は 4 つに分ける。**「索引にあるがいまは無い」を、そのまま削除と読まない**ためで、週次レビュー（`braindex review`）の
確認不能・対象外と同じ振り分けにした（[review-lint.md](review-lint.md)）。

| 差 | 意味 | どうするか |
|---|---|---|
| 未反映 | いま見つかるが索引に無い | `braindex` で再生成すると載る |
| 確認不能 | 索引にあるが、今回読めなかった範囲の中。有無は分からない | 読めない原因（権限・排他）を直してから再生成する |
| 対象外 | 索引にあるが、いまの設定では走査しない場所（`notes_dirs` を変えた・`archive/` へ移した・`exclude` に当たる）。理由を添える | 意図どおりなら再生成で消える。載せたければ設定か置き場を直す |
| 無い | 索引にあるが、置き場は確認できてそのパスに無い | 削除・改名なら再生成で消える |

`-path` に渡すパスは root 相対（索引のパス列と同じ形）。存在しないパスも問える（「この場所に置いたら載るか」の確認に使う）。

## フラグと終了コード

フラグ: `-config`（設定ファイル。既定はカレントの `braindex.json`。無ければ `-root` が必須）`-root`（設定の root より優先）
`-catalog`（保存済みの索引。既定は設定ファイルと同じディレクトリの `index/catalog.md`）`-date YYYY-MM-DD`（診断日の固定）
`-path <root 相対>` `-json`。位置引数は受け付けない。

終了コード: 0 問題なし（読めなかった範囲も警告も無く、保存済みの索引はいまの走査と一致）／1 失敗（フラグ・設定・root の誤り。診断は出さない）
／2 要確認（診断は出す）。2 になるのは次のどれか:

- いま走査しても索引に載るファイルが 1 件も無い
- いま走査すると読めなかった範囲がある
- 走査の警告がある（存在しない `extra` の起点など）
- 保存済みの索引が無い・読めない・braindex の書く形でない
- 保存済みの索引に走査の記録が無い（この記録を持たない版で生成）、または読めなかった範囲を残して作られた
- 保存済みの索引といまの走査に差がある（未反映・確認不能・対象外・無い のいずれか）

`-path` の結果は終了コードに影響しない（対象外のパスを問うても、それだけで 2 にはならない）。

## 決めたこと

- **走査は索引の生成と同じ `catalog.Build` で行う。** 診断用に別の走査を書くと、規則の差でいつか結果がずれ、「診断では見つかるのに索引に載らない」が起きる。ノートを全部読む分だけ生成と同じ時間がかかるが、それが「いま作ったらどうなるか」の正確な答えになる（2026-09-06）。
- **「いま」と「保存済み」を分けて出し、突き合わせる。** 保存済みの索引だけを読むと生成時の欠けが分からず、いまの走査だけを見ると索引が古いことに気づけない。両方を並べ、差を 4 種に振り分ける（2026-09-06）。
- **差はパスだけで突き合わせ、中身の変化（日付・タイトル・要旨）は見ない。** それは `braindex review` の担当で、診断は「載っているか・載れるか」に絞る（2026-09-06）。
- **終了コードは 0／1／2 に揃え、3 は使わない。** 「2 なら結果は使える」の共通規則に乗せる。`-path` の結果で終了コードを変えないのは、`-path` が問い合わせであって検査ではないため（2026-09-06）。
- **出力は規則ベース。** 同じ材料からは同じテキスト・同じ JSON になる（テスト `TestBuild_同じ材料なら同じ出力`）。診断した時点は `-date` の日付だけを載せ、時刻は載せない。索引の「生成:」行と同じ粒度にして、再現可能な出力を保つ（2026-09-06）。
- **対象外の理由は `scan.Covers` の判定に後付けするラベル。** 判定そのものは `Covers` に任せ、理由は「拡張子・archive・ドット始まりのリポ・extra の exclude か直下のみ・置き場の外」の粗い分類にとどめる。判定の規則をもう一度書き写すと、いつか `Covers` と食い違うため（2026-09-06）。
