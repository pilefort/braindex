# braindex learn — 学習の提案

[← README](../README.md) ／ [手引きの目次](README.md)

```
braindex learn                          # 直近 14 日（news.profile_days）の材料から 3 つの節を出す
braindex learn -top 5 -json             # 各節 5 件・JSON
braindex learn answer known istio       # 候補 istio に「既知」と回答する（次回から伏せる）
braindex learn answer later -until 2026-10-01 envoy   # 「後で」。10 月 1 日から再提示
braindex learn answers                  # 回答の一覧
braindex learn answer clear istio       # 回答を解除する
```

「いま学ぶと良さそうなこと」の候補を、手元の材料だけから規則ベース（LLM を使わず規則と閾値だけ）で出す。材料と窓は `braindex news profile` と同じ
（索引・セッションログ・`news/keep`・補助ファイル）。訂正の判定は `braindex retro` と同じ辞書（設定 `retro.dictionary` があればそれ）。
候補を出したあと、回答済み（[候補への回答](#候補への回答)）の候補を伏せ、「索引に無い」語をノート本文で照合する（`braindex search` と同じ走査規則・同じ検索処理）。
出力は語と件数と出典の位置（パス:行）だけで、発話やノートの本文は載せない。外には何も送らない。

| 節 | 条件 | 読み |
|---|---|---|
| 触れているが索引に無い | 会話（利用者とエージェント双方の本文）に 3 セッション以上出るのに、索引（全期間のタイトル・要旨）にも keep にも無い語。全セッションの 10% を超えて出る語は汎用語として除く | 本文でも未発見なら理解が定着していない候補（ノートに 1 本書くか学び直す）。本文で発見なら、ノートはあるが要旨から引けない（読み直すか要旨に語を出す） |
| 訂正の文脈に繰り返し出る | 訂正辞書に当たった発話と、その直前の発話に出る語。2 発話以上 | つまずきの周辺にある候補 |
| 残した記事にあるが索引に無い | keep の見出しにあるのに索引に無い語 | 本文でも未発見なら、読んで残したが自分の言葉にしていない候補。本文で発見なら、書いてはいるが要旨から引けない |

同じ冒頭（120 字）の発話が 3 セッション以上に現れるもの（40 字未満の短い発話は除く）は定型（`claude -p` の機械実行・貼り付け）として
訂正の文脈から除き、除いた数を材料の行に出す。この判定は読み取り層（`internal/sessions`）にあり、`retro` と `news` も同じ印を見る
（2026-09-06 に共通化。別々に持っていた頃は、同じログから機能ごとに違う数が出ていた）。URL は語にしない。索引が無い hub では「索引に無い」の判定が緩くなる（先に `braindex` で索引を作る。本文照合はそれでも走る）。
閾値はコードの既定値（v1・設定にしていない）。フラグは `-config` `-date` `-days` `-sessions` `-top` `-json`（位置引数は受け付けない。サブコマンドは `answer` と `answers` だけ）。
終了コード: 0 成功／1 失敗／2 警告つき（索引やセッションの置き場が無い・本文を読めなかった範囲がある・本文照合を飛ばした・回答ファイルが読めない）。

## 本文照合

索引にあるのはタイトルと要旨（先頭行の 80 字）だけなので、本文の後半に書いた語は「索引に無い」側に落ちる。索引は手がかりであって、
記録が無い証明ではない。そこで「触れているが索引に無い」「残した記事にあるが索引に無い」の語を、索引と同じ走査規則
（設定 `braindex.json` の `root`・`notes_dirs`・`extra`。`archive` の下は読まない）でノート本文に当て、各項目の末尾に結果を付ける。

```text
材料: ノート 12・セッション 40・訂正 3 発話・keep 2
本文照合: 41 ファイルを読んだ・確認できなかった範囲 1 件（この中にあるかは分からない）
- beta/docs/notes/locked/ — permission denied

## 触れているが索引に無い（3）

- kubernetes — セッション 4 本／本文で発見（3 行・2 ファイル）: alpha/docs/notes/cluster.md:7, beta/docs/decisions.md:3 ほか
- istio — セッション 3 本／本文でも未発見（走査した範囲は全部読めた）
- envoy — セッション 3 本／確認不能（読めなかった範囲がある）
```

- **本文で発見** … 語を含む行数・ファイル数と、先頭 3 件の位置（`パス:行`。パスは索引と同じ `root` 相対、順はパス → 行）。ノートはある
- **本文でも未発見** … 走査した範囲は全部読めたうえで、どのノートにも無い。この状態だけが「ノートに無い」と言える
- **確認不能** … 未発見だが読めなかった範囲がある（`本文照合:` の行にその範囲を列挙）。無いとは言えない
- 「訂正の文脈に繰り返し出る」は「ノートに無い」とは言っていないので照合しない
- root が無い・走査できない hub では照合を飛ばし、`本文照合: なし` と断ったうえで候補を索引だけの判定で出す（警告・終了コード 2）

`-json` は各項目に `evidence`（`status` = `found`／`absent`／`unknown`・`files`・`lines`・`locations[]{path,line}`）、全体に `verification`
（`done`・`words`・`files`・`gaps[]{rel,dir,reason}`・`complete`・`warnings`）を持つ。照合していない項目・照合前の出力ではどちらも省かれる
（既存の `word`・`sessions`・`corrections`・`keeps` は変えていない）。

## 候補への回答

候補は毎回ゼロから出すので、そのままだと「これは要らない」「もう学んだ」と決めた語が次の週も同じ節に出る。
`braindex learn answer` で回答を残すと、次回の提示からその候補を伏せ、伏せた数だけを出す。

```
braindex learn answer <known|unwanted|later|clear> [-section 節] [-until YYYY-MM-DD] <語> [<語>...]
braindex learn answers [-json]
```

| 回答 | 意味 | いつまで伏せるか |
|---|---|---|
| `known`（既知） | もう学んだ・知っている | 解除するまで |
| `unwanted`（不要） | 学ぶ対象ではない（製品名・汎用語など） | 解除するまで |
| `later`（後で） | いまは扱わない | `-until` の日の前日まで。既定は今日から窓の日数（`-days`・既定 14 日）後。その日から回答日つきで再提示する |
| `clear` | 回答を解除する | — |

- 語は出力に出ている綴りで指定する（ラテン文字の大文字は畳む。複数まとめて指定できる）。**いま候補に出ている語にだけ付けられる**
  （`-top` で隠れた分も対象）。候補に無い語なら何も書かずに終了コード 1——綴りの誤りを黙って記録しないため。`clear` は候補に無い語でも消せる
- 回答は**節と語の組**で持つ。同じ語が複数の節に出ていれば全部に付き、`-section unsettled`／`stumbles`／`read_not_written` で 1 つの節に限れる。
  「索引に無い」と言われた語が後に「訂正の文脈」に出るのは別の問いなので、回答は引き継がない
- 同じ節と語に回答し直すと置き換わる（前の回答は残らない）。何語かのうち 1 語でも失敗したら何も書かない
- `braindex learn` は回答を書き換えない。候補の根拠が変わっても（本文に書いた・索引に載った・件数が増えた）回答は消さない——候補が出なくなれば回答が効かないだけで、
  消すと窓の揺れで候補が戻ったときに本人に同じ判断をもう一度させることになる。要らなくなった回答は `braindex learn answers` で見て `clear` で消す
- 期限の来た「後で」も自動では消さない（一覧に「期限切れ」と出る。回答し直すか `clear`）

置き場は hub の **`work/learn/answers.json`**（節・語・回答・回答日・再提示日だけ。本文は書かない）。`work/` は揮発側（上書きされる・索引に載らない）で、
週次レビューの記録 `work/review/` と同じ扱い。回答は本人の入力で作り直せないので、`news/.seen.json` のような `.gitignore` の作業ファイルにはしない。
壊れていると、`braindex learn` は回答を反映せずに出して警告（終了コード 2）、`learn answer` と `learn answers` は失敗（終了コード 1・上に書かない）。直すかファイルごと消す。

```text
$ braindex learn answer unwanted istio
回答: 触れているが索引に無い: istio — 不要（2026-09-06）
保存先: work/learn/answers.json

$ braindex learn
材料: ノート 12・セッション 40・訂正 3 発話・keep 2
本文照合: 41 ファイルを読んだ・確認できなかった範囲なし
回答済み: 伏せた 1 件（既知 0・不要 1・後で 0）
```

`-json` は全体に `feedback`（`hidden[]{section,item,answer,date,until}`・`known`・`unwanted`・`later`・`expired`）を持ち、期限の来た「後で」の項目には
`deferred`（回答日）が付く。回答ファイルを読めなかったときは `feedback` を省く。

## 決めたこと

- **見出しは「ノートに無い」でなく「索引に無い」と言う（2026-09-06）。** 索引で判定した事実をそのまま言う。本文の照合結果は項目ごとに付け、
  「ノートに無い」と言えるのは「本文でも未発見」だけにする（設計レビュー補足 2026-09-06「索引に語がないことと、本文に記録がないことを分ける」）
- **読めなかった範囲があるときは「無い」と断定しない。** `braindex search` と同じで、未発見を「確認不能」に落とす。索引の「走査:」の記録と同じ考え方
- **候補の抽出と本文照合を分ける。** 抽出（`learn.Build`）は入出力なしで同じ材料から同じ結果、照合（`learn.Verify`）は本文を読む。
  検索の処理は `braindex search`（`internal/textsearch`）を呼び、複製しない。1 回の検索（全語をどれか 1 語・語の境界あり・大小無視）で読む
- **照合は候補を減らさない。** 発見した語も節に残し、結果を付けるだけ。`-top` で切った件数がそのまま出る。「索引の要旨から引けない」も
  読み手に伝える価値がある（要旨に語を出す・読み直す）
- **項目行には事実だけ、読み（どうするか）は節の説明に書く。** 事実（区分・数・位置）と学習上の解釈を混ぜない
- **本文の行は出力に載せない。** 出典は `パス:行` まで。発話の本文を載せない既定と同じ理由で、ノートの本文もどこにも書かず送らない
- **候補は節と語の組で識別する**（`learn.Report.Candidates()`）。「候補への回答（既知・不要・後で）」もこの識別で持つ（`learn.Feedback`）
- **回答は候補を出す側では書かない（2026-09-06）。** `learn.Apply` は渡された回答で候補を伏せるだけで、回答ファイルを書くのは `learn answer` だけ。
  提示のたびに本人の判断を上書きしない（判断は本人のもの）。伏せてから件数を切る（`Apply` → `Truncate`）ので、`-top` の件数がそのまま出る
- **「既知」「不要」に期限を持たせず、「後で」だけ再提示日を持つ。** 前者は判断そのもので材料や本文照合の結果が変わっても覆らない。後者は先送りなので日で戻す。
  既定の再提示日を窓の日数後にしたのは、その頃には材料（窓の中のセッション）が入れ替わっていて、それでも出るなら改めて判断する価値があるため
- **回答できるのは、いま候補に出ている語だけ。** 候補の集合は提示と同じ材料から全件で作る。綴りの誤りを黙って記録しないため。解除は候補に無い語でも消せる（古い回答の掃除）
- **壊れた回答ファイルの上には書かない。** `braindex learn` は反映せずに出して警告、`learn answer` は失敗にする（本文の変更の記録 `changes.json` と同じ考え方。黙って作り直すと本人の回答を失う）
